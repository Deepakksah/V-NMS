Jab V-NMS Dashboard par kisi device ka status Offline, Missing Ports, Blank Storage/Disks, ya Zero Traffic dikhta hai, to problem 6 alag-alag layers par ho sakti hai. Is document me un sabhi conditions ke root causes aur step-by-step verified solutions diye gaye hain.

⚡ 30-Second Fast Diagnostic Flowchart

🚨 Category 1: Physical & Link Layer Failures (Device Completely Offline)

Condition 1.1: Device Powered Off, Cable Disconnected, ya Switch Port Down

  • Symptom: Ping shows Destination Host Unreachable ya Request timed out (100% Packet Loss).
  • Root Cause: Power supply failure, patch cord loose, ya Cisco switch port err-disabled (BPDU guard / loop detection) state me chala gaya hai.
  • Diagnosis Command: 
    arp -a | findstr "TARGET_IP"
    Agar ARP table me MAC address nahi milta, to device local physical network par maujood hi nahi hai.
  • Solution:
    1. Physical NIC link light (Green LED) check karein.
    2. Switch CLI par port status verify karein: show interface status | include <port>
    3. Port recover karne ke liye: shutdown then no shutdown execute karein.

Condition 1.2: VLAN Mismatch (Wrong Switch Port Assignment)

  • Symptom: Link LED green hai, lekin subnet se koi communication nahi ho raha.
  • Root Cause: Switch port par galat Access VLAN configured hai (e.g. Target ko VLAN 10 me hona tha par port VLAN 1 par chal raha hai).
  • Solution: 
    interface GigabitEthernet1/0/15
 switchport mode access
 switchport access vlan 10

🛡️ Category 2: Routing & Firewall Drops (Ping Drop / Subnet Block)

Condition 2.1: Missing Default Gateway ya No Inter-VLAN Routing

  • Symptom: V-NMS apne subnet (172.168.1.0/24) ko scan karta hai, par doosra subnet (192.168.10.0/24) bilkul respond nahi karta.
  • Root Cause: V-NMS Server par gateway missing hai, ya Core Switch/Firewall subnets ke beech packets route nahi kar raha.
  • Diagnosis Command: 
    tracert -d TARGET_IP
  • Solution: Core Switch par ip routing verify karein aur firewall par inter-subnet rule allow karein.

Condition 2.2: Host Firewall (Windows Defender / Linux iptables) Blocking Ping

  • Symptom: Web/SSH chal raha hai, par ICMP Ping 100% loss dikhata hai aur device "Down" show hota hai.
  • Solution (Windows Server - Run as Admin): 
    netsh advfirewall firewall add rule name="Allow ICMPv4-In" protocol=icmpv4:8,any dir=in action=allow
  • Solution (Red Hat Enterprise Linux / Ubuntu): 
    sudo firewall-cmd --add-icmp-block-inversion
sudo firewall-cmd --reload

📡 Category 3: SNMP Telemetry Failures (Bandwidth, CPU, Memory Missing)

Critical Rule: Agar device PING ho raha hai lekin Interface Bandwidth (0 Mbps), Traffic Graphs, ya CPU/RAM blank dikha raha hai, to 95% cases me issue SNMP configuration ka hota hai.

Condition 3.1: SNMP Service Stopped ya Not Installed

  • Symptom: SNMP Query Timeout (UDP Port 161)
  • Fix (Windows Server): 
    Add-WindowsCapability -Online -Name "SNMP.Client~~~~0.0.1.0"
Start-Service -Name SNMP
Set-Service -Name SNMP -StartupType Automatic
  • Fix (Linux RHEL 9 / Ubuntu): 
    sudo dnf install -y net-snmp && sudo systemctl enable --now snmpd   # RHEL
sudo apt install -y snmpd && sudo systemctl enable --now snmpd      # Ubuntu

Condition 3.2: Community String Mismatch

  • Symptom: V-NMS poll karta hai par koi response nahi aata (Silent Drop).
  • Root Cause: V-NMS default public bhejta hai, jabki switch par custom string (e.g. corp_read_2026) set hai.
  • Solution (Cisco Switch): 
    snmp-server community public RO

Condition 3.3: SNMP "Allowed Management Hosts" ACL Restriction

  • Symptom: Switch/Server usi subnet par hone ke bawajood SNMP reject karta hai.
  • Root Cause: Device sirf purane monitoring server ke IP se query accept karta hai, aur naye V-NMS Server IP (172.168.1.14 / 172.168.1.11) ko whitelist nahi kiya gaya hai.
  • Solution:
    • Windows: services.msc → SNMP Service → Properties → Security Tab → Add V-NMS IP 172.168.1.14.
    • Linux (/etc/snmp/snmpd.conf): rocommunity public 172.168.1.14

💻 Category 4: Deep Server Telemetry (WMI / Database / Port Listening)

Condition 4.1: Service Bound to Localhost Only (127.0.0.1)

  • Symptom: Server ke andar app chal rahi hai, par V-NMS scan me Port 5432 (Postgres), 27017 (Mongo), ya 9090 (Cockpit) open nahi dikhta.
  • Root Cause: Service configuration me bind_ip sirf 127.0.0.1 par set hai.
  • Solution:
    • PostgreSQL (postgresql.conf): listen_addresses = '*' (aur pg_hba.conf me subnet allow karein)
    • MongoDB (/etc/mongod.conf): bindIp: 0.0.0.0

Condition 4.2: Windows WMI / RPC Error (0x800706BA "RPC Server Unavailable")

  • Symptom: Remote storage volume ya physical disk scan karte waqt DCOM timeout aata hai.
  • Solution (Target Windows Host par Admin PowerShell me chalaein): 
    winrm quickconfig -q
netsh advfirewall firewall set rule group="Windows Management Instrumentation (WMI)" new enable=yes
netsh advfirewall firewall set rule group="Remote Administration" new enable=yes

⚙️ Category 5: V-NMS Engine & Database Health

Condition 5.1: VNMSService Crash ya Stopped

  • Symptom: Browser me http://172.168.1.14:8081 par ERR_CONNECTION_REFUSED aata hai.
  • Solution: 
    Get-Service -Name VNMSService | Start-Service

Condition 5.2: PostgreSQL Database Connections Maxed Out

  • Symptom: Backend log me connection pool exhausted ya too many connections error aata hai.
  • Solution: C:\Program Files\PostgreSQL\18\data\postgresql.conf me max_connections = 200 karke service restart karein.
